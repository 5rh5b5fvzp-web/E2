# E2 企业开发规范清单（自检表）

> 对照实验二「双师课堂」企业开发规范整理，共 14 条，并给出本项目自检结果。

| 序号 | 规范条目 | 本项目落实情况 | 自检 |
| --- | --- | --- | --- |
| 1 | 分层职责边界清晰：Controller 只做参数接收与返回，Service 承载业务，Mapper 只做数据访问 | Controller 不写 SQL；业务校验、事务在 Service；Mapper 仅继承 BaseMapper | ✅ |
| 2 | 包结构按职责划分：config / controller / service / mapper / entity / dto / common / interceptor / aspect / util | 目录与包名一致 | ✅ |
| 3 | 依赖版本统一管理：版本号集中在 `pom.xml` properties，不散落 | Spring、MP、Druid、Jackson、Validator 版本均在 properties | ✅ |
| 4 | 配置与代码分离：数据库四要素放 properties，不硬编码 | `jdbc.properties` + `jdbc-local.properties`（已忽略） | ✅ |
| 5 | 口令、密钥不入库、不入 Git | 数据库口令在本机文件；登录口令存 SHA-256 摘要 | ✅ |
| 6 | 统一返回格式：code / message / data / timestamp | `common/Result` | ✅ |
| 7 | 参数校验前置：JSR303 注解 + `@Valid` + `BindingResult` | `Student`、`Score`、`LoginDTO` | ✅ |
| 8 | 全局异常处理：业务异常与系统异常分开，前端不暴露堆栈 | `GlobalExceptionHandler` | ✅ |
| 9 | 统一日志：请求入参、耗时、异常可追踪 | `WebLogAspect` + logback | ✅ |
| 10 | 事务规范：写操作加 `@Transactional(rollbackFor = Exception.class)`，避免自调用/private 方法 | 正常回滚已验证；三类失效场景有对照接口与测试 | ✅ |
| 11 | SQL 规范：避免 `SELECT *`，查询条件走索引，分页必须走分页插件 | 使用 MP 条件构造器；`stu_no`、`stu_name`、`class_id`、`score` 均有索引 | ✅ |
| 12 | 接口规范：RESTful 路径、统一复数资源名、正确使用 GET/POST/PUT/DELETE | `/api/students`、`/api/scores` | ✅ |
| 13 | 命名规范：类名大驼峰、方法和变量小驼峰、常量全大写、数据库下划线 | 全部一致 | ✅ |
| 14 | Git 规范：提交信息带 `feat/fix/docs` 前缀，按功能拆分提交，打版本标签 | 已按功能拆分提交，标签 `v1.0.0` | ✅ |
| 15 | 交付物完整：源码、SQL 脚本、ApiFox 集合、架构图、操作文档 | `sql/init.sql`、`docs/E2-apifox-collection.json`、`docs/架构图.md`、`docs/实验二-操作文档.md` | ✅ |
| 16 | 最小权限原则：不同角色只开放必要操作，后端统一鉴权 | `RoleInterceptor` + `@RequireRole`；学生仅能查看本人成绩 | ✅ |

## 补充说明

- 未使用 `SELECT *`：分页查询由 MyBatis-Plus 按实体字段生成列清单；统计在 Java 层完成。
- 未在 Java 代码中硬编码数据库账号口令。
- 前端页面不显示演示账号密码，也不自动填充账号密码。
- 事务失效场景通过 `/api/dev/tx/*` 接口复现，并由 `TransactionDemoServiceTest` 自动验证。
